# リコール対象車両照会アプリ

自動車の車台番号を使って、リコール対象かどうかと改修状況を照会する1画面のWebアプリケーションです。照会結果では、リコールの不具合部位を3D車両モデル上で強調して表示します。

> [!IMPORTANT]
> 本アプリのデータはサンプルです。リコール届出情報は実在情報を参考にしていますが、車台番号、個別車両、改修状況は架空です。実際の車両情報の確認には使用できません。

---

## アプリケーション概要

ユーザーは次の2つの方法で車両を指定できます。

- 車種とサンプル車両を選択する
- 車台番号を直接入力する

車両を照会すると、次のいずれかを表示します。

| 判定 | 条件 |
|---|---|
| リコール対象・未改修あり | 未改修のリコールが1件以上ある |
| リコール対象・すべて改修済み | リコールがあり、すべて改修済みである |
| 登録車両・対象リコールなし | 車両は登録されているが、リコール情報がない |
| 該当車両なし | 車台番号に一致する車両が登録されていない |

登録車両が見つかった場合は、3D車両ビューを表示します。リコールの不具合部位以外を半透明にし、部位を光らせてカメラを寄せます。強調中の部位は「注目部位：〜」として文字でも表示します。3D車両モデルは全車種共通の代表モデルで、実車の形状とは一致しません。

詳細な仕様は[`PRD.md`](./PRD.md)を参照してください。

### 使い方

1. 「車種」から車種（シエンタ／クラウン／RAV4）を選ぶ
2. 「サンプル車両」から車両を選ぶと、車台番号が自動入力される
   - 車台番号を直接入力する場合は、1〜2を省略してよい
3. 「リコール情報を確認」ボタンを押す
4. 判定結果と、車両情報・リコールごとの改修状況が表示される
5. 3D車両ビューで、不具合部位が光る（未改修は赤、改修済みは緑）
   - ドラッグで回転、ホイールで拡大・縮小できる
   - 「全体表示」で強調を解除できる

入力した車台番号は、前後の空白を除去し、英小文字を大文字に変換してから照会します。

### 動作確認に使える車台番号

`data/vehicles.json`のサンプルデータに対応しています。

| 車台番号 | サンプル車両 | 期待される判定 | 3D車両ビューの注目部位 |
|---|---|---|---|
| `MXPL10-9900001` | シエンタ サンプル車両001 | リコール対象・未改修あり | 乗車装置（シートベルト）（未改修） |
| `AXAP64-9900004` | RAV4 サンプル車両001 | リコール対象・未改修あり | 電気装置（モータ制御用コンピュータ）（未改修） |
| `MXPL10-9900002` | シエンタ サンプル車両002 | リコール対象・すべて改修済み | 乗車装置（シートベルト）（改修済み） |
| `AZSH32-9900003` | クラウン サンプル車両001 | リコール対象・すべて改修済み | 電気装置（コンビネーションメータ）（改修済み） |
| `MXPC10-9900005` | シエンタ サンプル車両003 | 登録車両・対象リコールなし | なし（全体表示） |
| `MXPL10-9999999` | （未登録） | 該当車両なし | 3D車両ビューなし |
| `  mxpl10-9900001  ` | （正規化の確認） | リコール対象・未改修あり | 乗車装置（シートベルト）（未改修） |
| （空欄） | — | 入力エラー | 3D車両ビューなし |
| `MXPL109900001` | （ハイフンなし） | 入力エラー | 3D車両ビューなし |

### 3Dモデル

3D車両ビューは、既定でCar Conceptを表示します。

> 3Dモデル：Car Concept by Eric Chadwick, © 2024 Darmstadt Graphics Group GmbH ([CC-BY 4.0](https://creativecommons.org/licenses/by/4.0/))
> 出典：[KhronosGroup/glTF-Sample-Assets](https://github.com/KhronosGroup/glTF-Sample-Assets/tree/main/Models/CarConcept)

RAV4風モデルを使う場合は、次のコマンドで取得します（任意）。ライセンス表記がないため、gitには含めず、社内ハンズオンの範囲でのみ使用してください（ADR-002）。

```bash
curl -L -o public/models/rav4.glb https://raw.githubusercontent.com/jnibarger01/toyota-showroom/HEAD/assets/imported/toyota-rav4-showroom.glb
```

## E2Eテストで確認する主要シナリオ

| No. | シナリオ | 期待結果 |
|---|---|---|
| 1 | 車種とサンプル車両を選択する | 対応する車台番号が自動入力される |
| 2 | 未改修車両を照会する | 「リコール対象・未改修あり」と表示される |
| 3 | 改修済み車両を照会する | 「リコール対象・すべて改修済み」と表示される |
| 4 | リコール情報のない登録車両を照会する | 「登録車両・対象リコールなし」と表示される |
| 5 | 未登録の車台番号を照会する | 「該当車両なし」と表示される |
| 6 | 車台番号が未入力のまま照会する | 入力エラーが表示される |
| 7 | 不正形式の車台番号を入力する | 入力エラーが表示される |
| 8 | 小文字と前後空白を含む車台番号を入力する | 入力が正規化され、該当車両を照会できる |
| 9 | 未改修のリコールがある車両を照会する | 「注目部位：（不具合部位）（未改修）」と表示される |
| 10 | 改修済みの車両を照会する | 「注目部位：（不具合部位）（改修済み）」と表示される |
| 11 | 3D車両ビューで「全体表示」を押す | 注目部位の表示が消える |
| 12 | 未登録の車台番号を照会する | 3D車両ビューが表示されない |

3D描画の中身（canvas内の色や形）は検証せず、画面上の文字表示で確認します。

## サンプルデータ

`data/vehicles.json`には、次の確認に必要なサンプルデータが含まれています。

- 未改修のリコールがある車両
- 3D車両ビューで強調する部位（各リコールの`partKey`）
- すべて改修済みの車両
- 対象リコールがない登録車両
- 複数の車種

未登録車両の確認では、JSONに存在しない形式上有効な車台番号を使用します。

サンプルデータを変更した場合は、PRD、画面表示、E2Eテストの期待値に影響がないか確認してください。

## 開発ルール

- `PRD.md`を要求の正とする
- 実装前に計画を提示し、人間が確認する
- 業務用語は`docs/glossary.md`に従う
- 技術構成は採用済みADRに従う
- PRDにない機能を独断で追加しない
- 実装後は人間による手動確認を行う
- E2Eテストの観点を人間がレビューする
- テスト失敗時は、実装とテストのどちらが原因か切り分ける
- 修正後は関連テストだけでなく、E2Eテスト全体を再実行する
- READMEには実際に確認できた手順だけを記載する
- 実在する個別車両の情報を追加しない

詳細なClaude Code向けルールは[`CLAUDE.md`](./CLAUDE.md)を参照してください。

## 対象外

本アプリでは、次の内容を扱いません。

- ログイン・認証
- データベース
- 外部API連携
- 車両データの登録・更新・削除
- 改修状況の更新
- 実在する個別車両の検索
- VINおよび車台番号の完全な規格チェック
- 本番運用向けのセキュリティ・監査・可用性設計
- GitHub ActionsによるCI/CD
- 車種ごとの専用3Dモデル
- 実車における部品の正確な位置の再現
- 3D表示のスマートフォン対応
